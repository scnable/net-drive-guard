# NetDriveGuard

NetDriveGuard 是一个 Windows 网络盘自动维护工具：在用户配置允许的范围内，确认服务器离线后取消失效映射，恢复可用后自动重连。它针对虚拟机或共享服务停止后残留网络盘、可能影响资源管理器使用的问题；托盘状态和提醒用于说明处理结果。

本文对应版本：`0.4.0-dev`（r23 预览版）。默认只监控和提醒；离线取消映射、恢复后自动重连和开机自启动均需手动开启。

## 解决的问题

虚拟机或 NAS 关闭、离开办公网络或断开 VPN 后，Windows 可能仍保留无法访问的 SMB 网络驱动器映射。部分环境下，这会导致打开“此电脑”长时间加载、右键菜单延迟，甚至文件资源管理器无响应。

本工具通过确认离线后取消失效映射、共享恢复后重新连接，减少手动处理次数。取消映射不会删除共享目录中的文件，也不保证立即解除已经发生的资源管理器阻塞。

## 运行环境

- 面向 Windows 10 / 11 x64 桌面环境。
- 独立运行版包含所需运行环境，无需另外安装 .NET。
- 从源码构建需要 .NET SDK，见下方“构建要求”。

## 首次配置

1. 运行 `NetDriveGuard.App.exe`，从托盘打开设置。在“常用设置”中填写要维护的盘符（例如 `Y:`）和共享地址（例如 `\\server\share`）。
2. 在常用设置中选择“确认服务器离线后取消失效映射”和“服务器恢复可用后自动重连”。两项均选择才包含完整的离线处理与恢复过程；都不选时仅监控提醒。
3. 只有需要独立账号时才填写高级设置中的凭据。迁移前手动停用旧脚本，避免重复维护同一盘符。
4. 在“监控设置”中选择检测模式。需要修改具体参数时，先选择“自定义”。
5. 保存配置后，双击托盘图标查看监控面板，确认状态和事件记录；也可以立即检查、暂停或恢复监控。

程序只处理配置的目标映射，不覆盖其他盘符映射、不强制关闭文件。实际操作失败会显示状态或事件，不能将“检测到服务器恢复”直接视为“网络盘已重连成功”。

## 当前能力

- 按选择取消离线目标映射，服务器恢复可用后修复缺失映射。

- 单实例托盘运行。
- WNet 网络驱动器映射只读查询。
- TCP 端口短连接探测。
- 共享目录可访问性只读探测与超时隔离。
- 动态分层检测、离线确认和恢复判定。
- 状态变化通知及通知冷却。
- 非敏感配置保存与运行时热应用。
- 脱敏事件持久化和最近 100 条事件恢复。
- 当前状态在窗口内查看，不再定时写心跳文件。
- 按严重级别和监控状态组合筛选事件。
- Windows 凭据管理器、受控映射修复和非强制取消。
- 可选登录启动；新建任务不配置崩溃重启。
- 设置分为“常用设置／监控设置／高级设置”三个页签，保存和取消按钮固定在底部；旧脚本配置需手动填写。
- 支持简体中文和 English，修改界面语言后重启生效。
- 支持选择配置与日志保存目录，以及直接打开该文件夹。
- 不含共享地址、用户名、事件描述和本机路径的诊断导出。
- `--demo` 安全演示模式和 `--smoke-test` 无窗口启动检查。

## 设置说明

### 常用设置

配置盘符、共享地址、离线取消映射、自动重连和开机自启动。两项映射自动操作可分别启用，也可都关闭，仅保留监控提醒。

“开机自启动”是在当前用户登录 Windows 后启动，不是在登录前运行。

### 监控设置

检查间隔、离线确认次数和连接超时始终显示。预设模式下三个参数置灰、不可编辑；切换为“自定义”后可修改，切换时保留当前显示数值。

| 检测模式 | 常规服务器连接检查间隔 | 参数编辑 |
| --- | --- | --- |
| 标准 | 5 秒 | 只读 |
| 快速 | 2 秒 | 只读 |
| 节能 | 30 秒 | 只读 |
| 自定义 | 1～1800 秒 | 可编辑 |

主动选择预设模式时，会填入对应周期，并恢复为 3 次离线确认、800 毫秒连接超时。自定义模式下，离线确认次数范围为 2～10 次，连接超时范围为 100～10000 毫秒。

上述周期不是完成断开或重连所需的时间。离线确认、失败重试、连接超时和共享服务恢复时间都会影响实际处理耗时。

### 高级设置

- **共享凭据**：仅自动重连需要独立账号时填写；用户名和密码都留空，则使用当前 Windows 身份或已保存凭据。
- **文件保存目录**：默认使用 `%LOCALAPPDATA%\NetDriveGuard`。可选择本机目录，并通过“打开文件夹”直达。保存后配置与日志切换到新目录，旧文件保留；不要使用被监控的网络盘。
- **界面语言**：支持简体中文和 English，保存后退出并重新运行程序生效；历史日志保留原文。

切换数据目录后，默认目录仍保存用于定位新目录的 `storage-path.json`。凭据和自启动任务由 Windows 管理，不随数据目录迁移。

重要状态变化通过托盘通知提醒；离线确认过程中的单次临时内部错误仅在面板保留，持续异常仍会提醒。需要排查问题时，可从托盘菜单导出脱敏诊断。

## 安全边界

- 用户名和密码只在更新映射凭据时输入，密码只保存到当前用户 Windows 凭据管理器。
- 配置、通知、事件和诊断不记录密码。
- 普通模式默认只观察；每次映射写入前重新查询并检查目标冲突。
- 迁移时请先手动停用旧脚本，程序不再查询固定名称的旧任务。
- 演示模式不访问网络，也不写入事件文件。
- 事件文件只在应用数据目录内按 5 MiB 和 3 个固定归档轮转。

## 构建要求

- Windows 10 或更高版本。
- .NET SDK 10.0.400。

```powershell
dotnet build NetDriveGuard.sln -c Release
```

公开仓库不包含 `tests` 测试源码，解决方案仅包含应用及其依赖项目。

生成 Windows x64 自包含单文件预览：

```powershell
.\scripts\publish-preview.ps1 -OutputDirectory artifacts\NetDriveGuard-preview
```

发布脚本拒绝覆盖已经存在的输出目录。

## 运行方式

普通启动会进入系统托盘：

```powershell
.\NetDriveGuard.App.exe
```

安全演示：

```powershell
.\NetDriveGuard.App.exe --demo
```

烟雾测试：

```powershell
.\NetDriveGuard.App.exe --smoke-test
```

关闭状态面板只会隐藏窗口。需要完全退出时，请右键托盘图标并选择“退出”。

## 当前限制

- 当前一次维护一个目标，不支持批量管理，也不会自动在内网 IP 与公网 IP 之间切换。
- 不覆盖同一盘符上指向其他位置的映射，不强制关闭正在使用的文件；文件占用可能导致取消映射失败。
- 不是通用的资源管理器修复工具。卡顿来自其他网络位置、失效快捷方式或系统问题时，仅处理当前映射不一定有效。
- 自动化测试和界面自检不能替代目标环境验收。SMB 服务、凭据、登录启动和实际文件占用情况，需要在自己的环境中确认。
- 长时间运行、实际日志轮转及不同干净目标机上的行为仍需进一步验证。
- 开发预览尚未进行数字签名。

当前已实现离线取消和恢复重连，不再仅限于只读原型。建议先确认目标环境下的离线处理、恢复重连和通知行为符合预期，再用于日常自动维护；不要同时运行管理同一盘符的旧任务。
